# Sécurité : suivi de la checklist

Fichier de suivi à tenir à jour à chaque changement de sécurité, avec une revue complète **chaque trimestre** (et avant chaque rentrée).

Légende : ✅ fait dans le dépôt · 🔧 à faire dans une console (Firebase, Google Cloud, GitHub, Vercel) · ⏳ à décider ou à compléter

| # | Thème | Statut | Ce qui est en place / ce qu'il reste à faire |
|---|---|---|---|
| 0 | Réflexes 1er commit | ✅ | `.gitignore` (secrets, `.env`, clés, fichiers générés). Aucun secret dans le dépôt : la configuration web Firebase (`apiKey`…) est publique par conception ; la sécurité repose sur les règles et App Check. Pas de backend, donc rien pour Secret Manager pour l'instant. La clé du compte de service CI est un secret GitHub. |
| 1 | Auth & comptes | ✅ / 🔧 / ⏳ | ✅ Mot de passe 16 caractères minimum (formulaire). ✅ Fail-closed : si Firebase ne démarre pas, l'appli bloque au lieu de basculer en mode local. ✅ Comptes nominatifs (un e-mail par établissement, adresse confirmée obligatoire pour écrire). 🔧 Imposer 16+ côté serveur : *Authentication › Paramètres › Règles relatives aux mots de passe*. 🔧 MFA : activer pour **vos comptes Google/Firebase d'administration** (console). La MFA des enseignants exige Identity Platform (SMS payant) : non retenue. ⏳ **Auto-inscription** : elle est au cœur du défi (chaque établissement s'inscrit). Pour la fermer : passer à Identity Platform et décocher *Activer la création (inscription)*, puis créer les comptes vous-même ; ou ajouter un code d'invitation vérifié par les règles. |
| 2 | Règles Firestore | ✅ / 🔧 | ✅ `firestore.rules` versionné : lecture publique limitée aux totaux, écriture par le seul propriétaire, types et bornes validés, une séance max par écriture, suppression de son compte. ✅ Déploiement automatique par GitHub Actions (`deploy-rules.yml`). Pas de Storage utilisé. 🔧 Vérifier que la base est en région UE (`eur3` ou `europe-west*`) : non modifiable après création. |
| 3 | Anti-abus | ✅ / 🔧 | ✅ Code App Check (reCAPTCHA v3) prêt : renseigner `APP_CHECK_SITE_KEY` dans `public/app.js`. 🔧 Créer la clé reCAPTCHA v3, l'enregistrer dans *App Check*, observer les métriques 1 à 2 semaines (**surveillance**), puis **Enforce** sur Firestore et Authentication. 🔧 *Google Cloud › API et services › Identifiants* : restreindre la clé API aux référents HTTP (`https://<votre-domaine>/*`, `https://hamburger-6d3aa.firebaseapp.com/*`) et aux seules API Identity Toolkit, Token Service, Cloud Firestore, Firebase Installations, App Check. |
| 4 | En-têtes HTTP | ✅ | `vercel.json` : CSP stricte (aucun script inline, aucun CDN de script hors reCAPTCHA), HSTS 2 ans + preload, `X-Frame-Options: DENY`, `frame-ancestors 'none'`, `nosniff`, `Referrer-Policy`, `Permissions-Policy`, COOP. Vérifier sur securityheaders.com après déploiement. |
| 5 | Dépendances | ✅ | Tailwind compilé et SDK Firebase **auto-hébergés** (`npm run build`, versions figées par `package-lock.json`) : plus de script tiers depuis un CDN. `npm audit` en CI. Dependabot hebdomadaire (npm + Actions) avec **délai de 7 jours** après publication, **majeures ignorées** (à faire à la main). Actions GitHub épinglées par SHA de commit. Override `@grpc/grpc-js` (dépendance Node seulement, absente du navigateur). |
| 6 | Analyse statique & CI | ✅ | `.github/workflows/ci.yml` : `npm audit`, ESLint avec `eslint-plugin-security` et `no-unsanitized`, build, Semgrep (`p/javascript`, `p/owasp-top-ten`, `p/secrets`). Lancé à chaque push, PR et chaque lundi. 🔧 Rendre ces contrôles obligatoires : *GitHub › Settings › Branches › règle de protection de `main`*. |
| 6 bis | CI/CD déploiement | ✅ / 🔧 | `deploy-rules.yml` : projet ciblé par son nom (`--project hamburger-6d3aa`), `--only firestore:rules`, Node 22 (LTS supportée), permissions GitHub en lecture seule, environnement `production`. 🔧 Créer un compte de service dédié avec le **seul** rôle *Firebase Rules Admin*, mettre sa clé JSON dans le secret `FIREBASE_SERVICE_ACCOUNT` de l'environnement GitHub `production` (avec approbation manuelle si souhaité). Mieux encore : Workload Identity Federation (sans clé). |
| 7 | Injections (XSS) | ✅ | Toutes les données affichées passent par `textContent` (`el()`), `innerHTML` n'est utilisé que pour vider des conteneurs. Contrôlé par ESLint `no-unsanitized`. Pas de console d'administration. Aucune URL construite à partir de saisies. |
| 8 | Exposition fichiers | ✅ / 🔧 | Seul `public/` est publié : `firestore.rules`, la documentation et la CI ne sont pas servis. `robots.txt`. 🔧 Alertes budget : *Google Cloud › Facturation › Budgets et alertes* (ex. 5 €, alertes à 50/90/100 %), et suivi de l'usage Firestore. |
